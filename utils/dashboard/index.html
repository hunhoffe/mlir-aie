    Key
    • Nightlies: every workflow with a schedule trigger, its last completed scheduled run (the badge links to it), how long it ran and waited for a runner, the runners it used, the commits between its last green run and this one, and its last 14 runs oldest to newest. Failing workflows sort first. A workflow is stale when nothing completed in twice its schedule interval (at least 36 hours).
    • Kernels: the latest published nightly per NPU from the kernel checks, summarized; the kernel checks page has the regressions, drift and charts.
    • Coverage: line coverage of the C++ sources from the nightly coverage build, total and per directory, with the change against the value 30 days earlier. Higher is better.
    • Sizes: the mlir_aie wheels the nightly wheel build produced, by platform, RTTI setting and Python, with the change over 30 days. Smaller is better.
    • Dependencies: the pinned Peano and LLVM, how old each pin is, and the open bump pull request when there is one. A bump PR that has been red for weeks is a maintainer problem hiding in a closed tab.
